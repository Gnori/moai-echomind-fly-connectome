02. 받아 쓰는 길 네 가지

쉬운 순서. 아래로 갈수록 준비가 늘어난다. 명령은 각 저장소 README 와 공식 페이지에서 옮겼고, 직접 돌려 보지는 않았다.

01 눈으로 보기 — 설치 없음 · 5분

  • male-cns.janelia.org — 공식 프로젝트. 3D 뷰어(Neuroglancer)와 세포 종류 탐색.
  • neuPrint — 계정을 만들면 연결을 질의할 수 있다.
  • FlyWire Codex — 다섯 데이터셋을 같은 화면에서(01). 구글 계정 로그인 필요.

02 데이터로 받기 — Python · 조회는 수 분, 통째로는 1~13GB

공식 예제(neuPrint):

# pip install neuprint-python   (neuPrint 에서 계정과 API 토큰 발급)
from neuprint import Client, fetch_neurons, fetch_adjacencies

client = Client("https://neuprint.janelia.org", dataset='male-cns:v1.0', token=token)

neurons, syndist = fetch_neurons("DNge104")           # 주석 · 신경망 분포
outgoing_edges, info = fetch_adjacencies("DNge104")    # 나가는 연결
incoming_edges, info2 = fetch_adjacencies(None, "DNge104")

형태(뼈대·메시)가 필요하면 navis 가 neuPrint 위에 얹혀 동작한다(pip install navis[all]). 통째로 받는 파일과 크기는 01 참고.

03 시뮬레이션 돌리기 — 배선도에 발화 방정식 붙이기 · 30분 ~ 두어 시간

널리 쓰이는 방식은 누적·발화(LIF) 모델이다. 뉴런을 「전압이 쌓이다 문턱을 넘으면 한 번 발화하고 초기화되는 것」으로 단순화하고, 특정 뉴런을 켜거나 끄고 신호가 어디로 퍼지는지 본다.

저장소 무엇 알아 둘 것
philshiu/Drosophila_brain_model 2024 Nature 논문 모델. FlyWire 기준, MIT. 정해진 주파수의 포아송 발화로 뉴런을 켜고, 연결을 0 으로 만들어 끈다 Colab 버튼으로 설치 없이 시작. 로컬 설치 10분(README). 결과 원본은 수 GB 라 외부 아카이브에
eonsystemspbc/fly-brain 같은 모델을 Brian2·Brian2CUDA·PyTorch·NEST GPU·GeNN 으로 돌리고 속도를 비교 뇌 모델만 있고 몸과 붙인 데모는 없다. 3월에 「초파리 뇌를 복제해 가상 몸을 움직였다」고 보도된 회사
seohyunjun/mps-malecns-model 맥(Apple Silicon)에서 MaleCNS 를 맥 GPU(MPS)로. 공식 feather 3개(약 1.1GB)를 받아 씀 개인 실험 저장소. LIF 방정식·연결 부호·정규화는 이 프로젝트의 가정이라고 스스로 명시

맥에서 MaleCNS 돌려 보기(저장소 README 절차):

git clone https://github.com/seohyunjun/mps-malecns-model.git
cd mps-malecns-model
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-lock.txt
.venv/bin/python -m malecns download      # 공식 feather 3개, 약 1.1GB, SHA-256 검증
.venv/bin/python -m malecns prepare       # graph.npz
.venv/bin/python -m malecns doctor
.venv/bin/python -m malecns run --device mps --steps 100 --stimulus-type DNp01
  • DNp01 은 도망 반응에 관여하는 하강뉴런. 이 예제는 그 두 뉴런에 자극을 넣어 신호가 퍼지는지 보는 동작 확인이지 행동 재현이 아니다.
  • 결과: outputs/latest/summary.json, activity.npz (body_ids, spike_counts, population_spikes, final_voltage).
  • GPU 연결 배열만 약 512MB. 메모리가 모자라면 --chunk-size 250000.

mps-malecns-model 이 받는 입력과 내는 출력 — 소스(malecns/*.py)에서 읽은 것

「어떤 신호를 줄 수 있고, 어떤 신호를 돌려받나」. README 가 아니라 cli.py·model.py·recording.py·rl.py·data.py 코드 기준이다.

뉴런 하나의 방정식(model.py) — Shiu 모델(09)보다 더 단순하다.

v[t+1] = exp(−dt/tau) · v[t] + gain · (들어온 발화 × 연결 세기 합) + drive[t]
발화:  v ≥ 1.0  →  v = 0 으로 초기화        # 문턱 1.0 고정, 단위 없는 값(mV 아님)
전달 지연 한 스텝 · 불응기 없음 · 가소성 없음

줄 수 있는 신호(입력)

자리 명령 인자 무엇 한계
자극 대상 --stimulus-type DNp01 주석의 type 이름과 정확히 같은 뉴런 전부(예: DNp01 두 개) 한 번에 한 종류. 세포 ID 지정 없음. 종류가 없으면 오류
자극 세기 --stimulus 0.2 그 뉴런들에 매 스텝 일정하게 더하는 전압 증분(문턱 1.0 기준 → 배경 0.02 와 합쳐 여섯 스텝째에 발화) 상수. 시간에 따라 바뀌는 입력·포아송 입력은 명령줄로는 불가
배경 입력 --drive 0.02 모든 뉴런에 매 스텝 더하는 값. 기본값이면 정상 상태 전압 ≈ 0.41 이라 저절로 발화하지 않음 균일값 하나. 종류별 배경 발화(09 의 FLYCNS 문제)는 못 준다
방정식 --dt-ms 1 --tau-ms 20 --gain 1 스텝 길이, 막 시간 상수, 시냅스 입력 배율 문턱은 1.0 고정
그래프 prepare --max-neurons N 디버그용 부분 그래프(작은 bodyId 순이라 대표성 없음)
기록 대상 --record-neurons 256 시간별 기록을 남길 뉴런 수 — 자극 뉴런 먼저, 나머지는 씨앗 0 난수 표본 steps × 기록 수 ≤ 2천만

명령줄이 막아 둔 것은 파이썬으로 부르면 열린다. ConnectomeLIF.forward(drive) 가 「뉴런 수 길이의 텐서」를 받으므로 매 스텝 다른 값, 세포마다 다른 값을 줄 수 있다. 저장소의 rl.py 가 실제로 그렇게 쓴다 — 하강뉴런 네 종류(DNp01 위 · DNp10 아래 · DNa02 왼쪽 · DNge104 오른쪽)에 목표까지의 거리 × 0.16 을 방향별로 넣고, 그 세포와 하류 128개의 활동을 읽는다. 설계(06) 의 「① 감각 인코딩 → 광수용체 인덱스별 밝기」도 이 길로 넣는다.

from malecns.model import ConnectomeLIF
import numpy as np, torch
g = np.load("data/graph.npz")
model = ConnectomeLIF(len(g["body_ids"]), g["source"], g["target"], g["weight"], device="mps")
drive = torch.zeros(len(g["body_ids"]), device="mps")
for step in range(1000):
    drive[my_sensory_indices] = brightness_this_ms      # 세포별·스텝별로 다르게
    spikes = model(drive)                               # 전체 뉴런 bool 텐서, 이번 스텝 발화
    dn_activity = spikes[dn_indices]                    # 읽고 싶은 뉴런만 골라 읽기

돌려받는 신호(출력)

파일 배열·항목 뜻
activity.npz spike_counts (뉴런 수) 뉴런마다 누적 발화 수 — 전체, 표본 아님
population_spikes (스텝 수) 스텝마다 전체 발화 합
final_voltage (뉴런 수) 마지막 스텝의 전압 — 전체
recorded_indices · recorded_spikes (스텝×기록 수, 0/1) · recorded_voltage (스텝×기록 수) 고른 뉴런의 스텝별 발화·전압 시계열
body_ids · cell_types 인덱스 ↔ bodyId ↔ type 대응
summary.json total_spikes active_neurons stimulated_neurons steps_per_second simulated_ms … 실행 요약 + 그래프 메타데이터
report.html 3D 위치에 발화 표시 + 활동 상위 64개 래스터 서버·외부 자원 없는 단일 파일
train-rl 의 neural_features.npz policy.pt training.json 25칸 상태마다 (발화율, 마지막 전압) 특징 · 학습된 읽기층 커넥톰은 고정, 읽기층(32 은닉)만 학습

파이썬으로 부르면 매 스텝 model.spikes(전체 뉴런의 이번 스텝 발화) 와 model.voltage(전체 전압) 를 그대로 읽는다. 설계의 「③ 읽기·요약」이 쓰는 원재료가 이것이다.

그래프를 만들 때 정해진 것(data.py) — 결과 해석에 영향이 크다

  • 뉴런: superclass 가 있고 glia 가 아닌 것 전부(약 16.5만). graph.npz 에는 type 만 남고 superclass 는 저장되지 않는다 — 「하강뉴런 전부」처럼 superclass 로 고르려면 주석 feather 를 따로 읽어 인덱스를 만들어야 한다.
  • 부호: consensus_nt 로 아세틸콜린 +1 · GABA −1 · 글루탐산 −1, 나머지 전부 0. 즉 도파민·세로토닌·옥토파민·히스타민 출력이 0 이다. 광수용체는 히스타민이라 광수용체에 자극을 넣어도 다음 단(라미나)으로 퍼지지 않는다 — Fly.exe 와 같은 선택(10). 시각 입력은 라미나 L1~L3 에 넣거나, SIGNS 에 histamine: −1 을 더해 다시 prepare 해야 한다.
  • 세기: 연결의 시냅스 수를 받는 뉴런의 들어오는 시냅스 총합으로 나눈 비율 × 보내는 뉴런의 부호. 「시냅스 수 × 0.275 mV」(Shiu) 가 아니라 정규화된 값이라 gain 의 뜻이 다르다.
  • 연결: 공식 minconf-0.5 표 그대로, 시냅스 수 문턱 없음(2,556만 연결 전부).

설계와 견주면 — 뇌 통째로 맥 GPU 에서 돌리기·세포별 입력·전체 발화 읽기는 된다. 없는 것은 ① 눈(옴마티디아) → 광수용체 대응표, ② 히스타민 부호, ③ 종류별 배경 발화, ④ 하강뉴런 목록(superclass) — 넷 다 바깥에서 만들어 붙이는 것이고, 06 의 2장이 그 자리다.

04 몸에 붙이거나 응용하기 — 사람이 설계하는 부분이 커진다

  • 몸: FlyGym / NeuroMechFly v2 — 2026년 3월 2.x 로 바뀌어 옛 튜토리얼과 호환되지 않음(1.x 는 flygym-gymnasium). CPU 약 2배 실시간, GPU(Warp) 약 60배 실시간. flybody — 딥마인드·자넬리아의 물리 시뮬레이션 몸.
  • 시각: flyvis — 연결 지도를 제약으로 쓴 시각계 모델, 학습된 모델 포함, 실험 기록으로 검증(2024 Nature).
  • 목록: awesome-fly — 게임·데스크탑·연구 도구.

응용의 구조는 대체로 같다. 바깥 입력을 감각 뉴런에 넣고 → 배선도로 신호를 퍼뜨리고 → 특정 뉴런의 활동을 조작 신호로 바꾼다. 첫 단계와 마지막 단계는 사람이 정한 대응이다.
