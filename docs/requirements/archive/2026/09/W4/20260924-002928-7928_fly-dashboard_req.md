## 1. 요구사항 분석

- **문제**: 30 시간짜리 실행(`bin/run_full_v4.sh`)과 결과 파일(판정 · 관문 · 캡션 평가 · 성적표 · 봉우리)이 `runs/` 여기저기에 흩어져 있어 명령 여러 개로 봐야 한다. 요구자도 세션도 한눈에 못 본다.
- **목표**: `runs/` 만 읽어 HTML 한 장을 만든다. 브라우저에서 자동 갱신으로 본다. 학습에 영향이 없다(CPU 거의 0 · 파일 읽기만).
- **제약**: 무거운 실행 잠금 · 학습 프로세스를 건드리지 않는다(읽기만) · `runs/` 는 git 밖(결과 페이지도 git 밖 `runs/dashboard/`) · 설정 값은 코드에 박지 않는다(`config/dashboard.yaml`).
