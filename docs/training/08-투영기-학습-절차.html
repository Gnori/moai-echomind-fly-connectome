08. 투영기 학습 절차

2부 Qwen 연결 · 셋째 장. 코드: src/moai_echomind_fly/loop/train.py(한 걸음) · train_cli.py(순서 · 규칙) · guard.py · bin/run_full.sh · 설정 config/guard.yaml. 증거: W loop 2 · 3.1 · 3.2.

1. 한눈에

단계 질문 → 정답 바퀴 걸음 수 옵티마이저
① 정렬(캡션) "지금 무엇이 느껴지나?" → 캡션 2 581 × 2 = 1,162 AdamW 새로
② 행동 "지금 어떻게 움직일까?" → 행동 JSON + 캡션 30 % 섞기 1 581 + 174 = 755 AdamW 새로(train-v2)

한 걸음 = 예시 하나(배치 1). 진짜 배선과 섞은 배선을 똑같은 절차 · 같은 씨앗 순서로 따로 학습한다 — 대조군.

2. 학습 규칙 — TRAIN_RULE(판 train-v2)

TRAIN_RULE = {
    "version": "train-v2",
    "k": 2, "width": 256, "kind": "mlp2", "lr": 2e-4,
    "caption_epochs": 2, "action_epochs": 1, "caption_rehearsal": 0.3,
    "val_samples": 24, "seed": 0,
}
값 뜻
lr 2e-4 AdamW 학습률 · 가중치 감쇠 0.01
caption_rehearsal 0.3 행동 단계에 캡션 예시를 표본의 30 % 섞는다 — 같은 투영기로 글 질문엔 글로, 행동 지시엔 JSON 으로 답하게
val_samples 24 바퀴가 끝날 때마다 eval 나눔 앞 24 개로 검증 손실(캡션 · 행동 둘 다)
seed 0 예시 순서를 섞는 난수 씨앗(⚠️ 투영기 초기값에는 씨앗을 주지 않는다 — 10장 잔여 이슈)

판 변천: train-v1 은 행동 단계가 캡션 단계의 옵티마이저를 이어 썼다. v1 캡션 저장본에는 옵티마이저 상태가 없어서, 진짜 배선만 이어 돌리면 대조군과 절차가 달라진다 → train-v2 는 두 뇌 모두 행동 단계를 새 옵티마이저로 시작한다. 캡션 단계는 v1 과 같다.

3. 손실 — 정답 글 토큰의 교차 엔트로피

입력 임베딩 = [ 프롬프트(자리 표시 18 개 → 투영기 출력) , 정답 토큰 (마지막 하나 뺌) ]
손실       = 프롬프트 끝부터 나오는 로짓 vs 정답 토큰 + <|im_end|>   의 평균 교차 엔트로피

기울기는 Qwen 을 거꾸로 지나 투영기에만 닿는다. Qwen 은 얼려 있어 지나가기만 한다.

⚠️ 캡션 손실은 서식 글자까지 전부 맞히는 손실이다. "다가오는 물체: … / 먹이 냄새: …" 의 틀 글자는 매번 같아서 쉽게 맞히고, 정작 가려야 할 칸(왼쪽/오른쪽 · 개수)은 토큰 몇 개뿐이다 — 손실이 0.1 까지 내려가도 칸은 못 맞힐 수 있다(09장 · 10장).

4. 한 걸음 안에서 — 층별 역전파

4.1 왜 필요했나

처음엔 mlx 의 보통 방식(한 번에 미분)으로 돌렸다. 한 걸음 최대 메모리가 토큰당 약 0.32 GB 였다(226 토큰 → 102 GB · 191 토큰 → 90 GB). Qwen3.8 의 선형 어텐션 층 48 개는 학습 모드에서 미분 가능한 경로를 타는데, 그 경로가 토큰마다 상태(층당 3 MB)를 남긴다. mlx-lm 의 층별 재계산(grad_checkpoint)은 전체를 한 번에 평가하는 지연 평가에서는 듣지 않았다(켜도 꺼도 90~100 GB).

4.2 어떻게 하나 — Trainer.grads

1. 투영기로 입력 임베딩 x 를 만든다(여기서는 기울기를 끊는다)
2. 앞으로: Qwen 을 평가 모드(전용 커널 · 빠름)로 한 층씩 — 층마다 입력만 저장하고 즉시 평가
3. 머리: 마지막 은닉 → 정규화 → lm_head → 손실, 마지막 은닉에 대한 기울기(cot)
4. 거꾸로: 학습 모드로 바꿔 마지막 층부터 한 층씩 vjp(저장한 입력으로) — 층마다 평가해 끊는다
5. 임베딩에 대한 기울기(cot)를 얻으면 ⟨투영기 임베딩, cot⟩ 의 기울기 = 투영기 기울기

한 번에 한 층 몫만 메모리에 든다. 결과는 한 번에 미분한 것과 같다 — 작은 가짜 Qwen 으로 두 방식을 나란히 돌려 1e-6 안에서 확인했다(tests/test_train_layerwise.py).

4.3 걸음마다

AdamW.update → 평가 → mx.clear_cache(). 캐시 상한은 2 GB(training_cache_limit_gb). 캐시를 비우지 않았을 때는 걸음마다 쌓여 13 시간 뒤 103 GB · 스왑 42 GB 까지 갔다(2026-09-22).

고치기 전 고친 뒤
걸음 사이 캐시 74.7 → 76.3 GB 0.2 GB
한 걸음 최대 101.8 GB 32 GB(Qwen 29 GB 포함)
걸음당 시간 92~314 s 13~23 s(측정) · 실제 학습 5.6~7.6 s

5. 메모리 가드 — 학습 전용 규칙

맥 한 대의 통합 메모리를 요구자 화면 · 에코마인드 라이브 · 다른 세션과 같이 쓴다. 정본은 config/guard.yaml.

때 조건 어기면
시작 전 시스템 메모리 여유 ≥ 80 %(학습만의 예외 · 요구자 2026-09-22) · 잠금 runs/.heavy.lock 이 비어 있음 시작하지 않는다(끝 코드 2)
도는 중(5 걸음마다) 여유 < 25 % 또는 프로세스 전체 > 50 GB 그때까지의 투영기를 aborted-<단계>.safetensors 로 저장하고 멈춘다(끝 코드 3)
평가 · 성적표 평소 문턱 40 % + Qwen 28 GB 시작하지 않는다

6. 명령

# 새 종류의 무거운 실행 전에는 먼저 짧게 잰다 (저장 없음 · 기록 runs/train-probe-*.jsonl)
uv run fly-connectome train-probe --steps 12

# 한 뇌씩
uv run fly-connectome train --brain real      # 기본 --dataset main --val eval (runs/dataset-* 조각)
uv run fly-connectome train --brain rewired

# 캡션 단계 저장본에서 이어 행동 단계만
uv run fly-connectome train --brain real --resume-caption runs/projector-real-train-v1/stage1-caption.safetensors

# 전체 순서: 학습 둘 → 캡션 평가 넷 → 성적표 (단계마다 메모리 여유가 돌아올 때까지 30 분까지 기다림)
bin/run_full.sh
bin/run_full.sh --resume-real <진짜 배선 캡션 저장본>

⚠️ train 의 --dataset · --val 은 지금 runs/dataset-<이름> 조각을 읽는다(fly-loop-v1 묶음이 아니라). 묶음과 같은 내용이다.

이어 가기의 세부: 저장본을 불러오고 → 캡션 단계가 썼을 난수만 소비해(순서를 건너뛰기) → 행동 단계의 예시 순서가 처음부터 돈 것과 같게 한다. 저장본의 sha256 을 meta.json 의 caption_stage_from 에 남긴다.

7. 결과물 — runs/projector-<뇌>-train-v2/

파일 내용

8. 걸리는 시간 (실측 · 2026-09-22~23)

무엇 시간
진짜 배선 — 행동 단계만(이어 가기) 22:07 → 23:37 · 1.5 시간
섞은 배선 — 전체 23:37 → 02:52 · 3.3 시간

오래 도는 것을 띄웠으면 수십 분 간격으로 train.log 의 [mem] 줄과 memory_pressure 를 확인한다.

9. 확인 체크리스트

  • [ ] 시작 전 memory_pressure | tail -1 ≥ 80 % · ollama ps 로 다른 큰 모델이 없는지
  • [ ] train.log 의 [mem] 이 평탄(peak 약 32 GB · cache < 1 GB)
  • [ ] 끝나면 meta.json 의 qwen_fingerprint.unchanged: true
  • [ ] 학습 규칙을 바꿨으면 TRAIN_RULE.version 을 올렸다(결과 폴더 이름이 바뀐다)
