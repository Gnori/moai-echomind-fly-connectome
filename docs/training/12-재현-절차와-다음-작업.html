2. 한 일을 그대로 다시 하는 순서

각 단계: 스크립트 · 명령 · 입력 · 결과 파일 · 실측(시간 · 메모리) · 확인값. 앞 단계의 확인값이 맞지 않으면 다음으로 가지 않는다.

⚠️ 10-14 상태: 4.1 은 train-v7 로 해 봤다(성적표 p 0.056 · 못 넘음 · 10장 2.8 · 2.9) · 4.2 는 시야 대응표 대조를 못 넘어(물체 쪽 0.794 대 0.797 · 0.775 · p 0.064) 학습까지는 안 했다 · 4.3 은 버섯체 범위로 1 단계(CMA-ES)만 했고 대리 기울기 2 단계는 하지 않음 — R-7469 검증완료(요구자 "성공 가능성이 낮은건 하지마"). 아래 표는 그때 적은 설계안 그대로 둔다.

4.1 행동 단계가 캡션을 깎는 문제

항목 내용
왜 v5 · v6 모두 캡션 단계본 > 최종본이다(v6 냄새 쪽 0.577 → 0.530 · 움직임 통과 → 불통). 행동을 배우며 캡션이 잊힌다
어떻게 후보 ① train-v7 = v6 + caption_rehearsal 0.3 → 0.5(같은 자료 fly-loop-v4 · 뇌 4) · ② 캡션 · 행동을 번갈아(회전마다 섞기 — 코드 없음)
명령 초안 TRAIN_RULE 판 올림(train-v7) → train-probe --dataset fly-loop-v4 --steps 12 → v6 스크립트를 바탕으로 bin/run_full_v7.sh(만들 것)
대조군 재배선 s0~s2 를 같은 규칙으로
성공 기준 최종본 냄새 쪽 ≥ 캡션 단계본 · 성적표 vector 가 재배선 셋 모두 위
무게 학습 뇌 4 약 1.5 일(추정 · v6 실측 뇌당 5~10 h) + 성적표 약 12 h
먼저 잴 것 ⚠️ 성적표 씨앗 40 은 95 % 구간 폭이 약 ±0.15 — 0.350 대 0.375 는 가를 수 없다 → 씨앗 100 이상(성적표 약 30 h · 추정)을 먼저 검토 · scorecard_abort_footprint_gb 가 아직 없으니 성적표 프로세스 메모리부터 잰다

4.2 시야 방위 입력(retino-v2) — "물체 쪽" 칸

항목 내용
왜 v6 에서 물체 쪽 칸이 불통(0.506 · 찍기 0.506). 지금 시각 입력은 고도만 조율한다(vision.mode: retinotopic)
어떻게 config/task.yaml encoder.vision.mode: retinotopic2(고도 × 방위 가우시안 · 코드 있음 loop/encoder.py) · azimuth_sigma_deg 값을 선언해야 한다(지금 설정에 없음 · 출처 또는 "선언") · 판 올림
명령 초안 retinotopy build(retino-v2) → replay --pack fly-loop-v4 --split eval --name <이름> --rewired-seeds 0-2 --verify 6(검증 · 이때 --no-retune 없이 시각을 새 규칙으로 다시 조율) → 본 재생 → 묶기 → linear-probe --dataset <새 묶음>
대조군 재배선 + 뒤섞은 대응표 retinotopy build --shuffle azimuth --within type_side(같은 종류 · 같은 쪽 안에서 섞음) · --within type(두 눈을 섞어 좌우까지 지움 · ebff77a)
성공 기준 시각 → 물체 쪽이 찍기(대비 p < 0.05) · 재배선 · 뒤섞은 대응표 모두 위
무게 재생 — 뇌 수 × 결정 수에 비례(M3 실측 뇌 둘 결정당 약 4.6 s) · 전체 시간은 기록 없음
먼저 잴 것 --verify 로 결정당 시간 · 메모리

4.3 회로 학습 F-006 (세포 유형 단위)

항목 내용
왜 조향 하강 뉴런 DNa02 가 냄새에 침묵(M1) — 냄새가 행동 출력까지 닿지 않는다. 연결 하나하나가 아니라 세포 유형별 매개변수만 배워 커넥톰 정체성을 지킨다(R-7469 F-006 · 연구 노트 13 §2)

4.4 판을 바꿔 다시 할 때 — 순서

위 설계안(4.1 ~ 4.3)이나 다른 개선을 실제로 할 때의 순서다(scripts/README.md §4 와 같다).

  1. 바꿀 설정의 판을 올린다 — 옛 판은 config/archive/ 로 · 무엇을 다시 해야 하는지는 11장 §3.
  2. 과제를 바꿨으면 몸 확인 scripts/20-odor/m4-body-check.sh → 입력 크기가 판정 문턱에 닿는지 scripts/50-analysis/lr_budget.py.
  3. 판정 규칙은 결과 보기 전에 코드에 적는다(stats-v3 처럼).
  4. 수집은 작게 먼저 — scripts/10-data/collect.sh(collect-probe 를 먼저 돈다) 또는 채널 · 시야만 바꿨으면 scripts/10-data/replay.sh(원본과 같은지 먼저 검증).
  5. 묶은 뒤 config/datasets.yaml 의 current 를 새 묶음으로 바꾼다(한 줄) — 그 뒤 명령들의 --dataset 기본값이 새 묶음이 된다. 옛 결과를 다시 볼 때는 --dataset 을 직접 준다.
  6. 학습 판을 올리면 bin/run_full_v6.sh 를 복사해 새 판 순서를 만들고, config/dashboard.yaml 의 train_rule · plan 을 바꾼 뒤 대시보드를 다시 띄운다.
  7. 끝나면 scripts/90-wrap/finalize.sh <판> → 10장 대장 · R · 인수인계 · 문서 반영(2.8).
