## 1. 한눈에

| 단계 | 질문 → 정답 | 바퀴 | 걸음 수(v1 자료) | 옵티마이저 |
|---|---|---|---|---|
| **① 정렬(캡션)** | "지금 무엇이 느껴지나?" → 캡션 | 2 | 581 × 2 = **1,162** | AdamW 새로 |
| **② 행동** | "지금 어떻게 움직일까?" → 행동 JSON **+ 캡션 30 % 섞기** | 1 | 581 + 174 = **755** | AdamW **새로**(train-v2 부터) |

한 걸음 = 예시 **하나**(배치 1). 진짜 배선과 재배선을 **똑같은 절차 · 같은 씨앗 순서**로 따로 학습한다 — 대조군. v4 부터는 재배선을 **여럿**(최소 3 · `rewired-s0` … `s2`) 학습한다.
v2 자료(결정 약 3 천)면 걸음 수도 약 5 배가 된다.

## 2. 학습 규칙 — `TRAIN_RULE`(판 `train-v4`)

```python
TRAIN_RULE = {
    "version": "train-v4",
    "input": "compress", "compress": "compress-v2",   # v1 은 두 뇌의 차원이 달라 v2(같은 64)로
    "k": 1, "width": 0, "kind": "linear", "lr": 2e-4,
    "caption_epochs": 2, "action_epochs": 1, "caption_rehearsal": 0.3,
    "val_samples": 24, "seed": 0, "init_seed": 0, "template_weight": 0.1,
}
```

| 값 | 뜻 |
|---|---|
| `input` · `compress` | 입력 = **압축 관문을 통과한 채널의 압축 벡터**(09장 4절 · `runs/compress-<자료>-compress-v2/` · 자료 v2 는 시각 · 촉각 · 미각 · 몸 각 64 차원). 통과 채널이 0 이면 학습하지 않는다 |
| `kind` · `k` · `width` | 채널당 **선형 → 토큰 1 개**(07장 4.2) |
| `lr` 2e-4 | AdamW 학습률 · 가중치 감쇠 0.01 |
| `caption_rehearsal` 0.3 | 행동 단계에 캡션 예시를 표본의 30 % 섞는다 — 같은 투영기로 **글 질문엔 글로, 행동 지시엔 JSON 으로** 답하게 |
| `val_samples` 24 | 바퀴가 끝날 때마다 `eval` 나눔 앞 24 개로 검증 손실(캡션 · 행동 둘 다) |
| `seed` 0 | 예시 순서를 섞는 난수 씨앗 |
| `init_seed` 0 | 투영기 **초기값**의 씨앗(train-v3 부터) — 같은 규칙이면 같은 초기값에서 시작한다 |
| **`template_weight`** 0.1 | 손실 가중 — **칸 값 토큰 1 · 틀 토큰 0.1**(3절) |

**판 변천**:

| 판 | 무엇이 달라졌나 | 결과 폴더 |
|---|---|---|
| train-v1 | 첫 판 — 행동 단계가 캡션 단계의 옵티마이저를 이어 씀 | `runs/projector-real-train-v1`(캡션 단계만) |
| train-v2 | 행동 단계는 새 옵티마이저(v1 캡션 저장본에 옵티마이저 상태가 없어 진짜 배선만 이어 가면 대조군과 절차가 달라지기 때문) | `runs/projector-{real,rewired}-train-v2` — **지금 결과** |
| train-v3 | + 초기값 씨앗 · 묶음 자료를 직접 읽음(v2 까지는 초기값이 실행마다 달라 같은 설정으로도 같은 저장본이 나오지 않았다 — 시험 `test_projector_init_seed_makes_same_weights`) | 돌리지 않음 |
| **train-v4** | + **압축 입력 · 채널당 선형 토큰 1 · 칸 값 토큰 가중 · 재배선 `rewired-s<K>` · 기본 자료 `fly-loop-v2`** | `runs/projector-{real,rewired-s0,…}-train-v4` — 자료 v2 뒤 |

GPU 는 계산 순서에 따라 기울기가 조금씩 흔들릴 수 있어서(4.2 의 시험 머리말), **학습이 끝난 저장본까지 비트 단위로 같은지는 아직 재 보지 않았다.**

## 3. 손실 — 정답 글 토큰의 교차 엔트로피 (v4: 칸 값에 가중)

```
입력 임베딩 = [ 프롬프트(자리 표시 → 투영기 출력) , 정답 토큰 (마지막 하나 뺌) ]
손실(v2)   = 프롬프트 끝부터 나오는 로짓 vs 정답 토큰 + <|im_end|>   의 평균 교차 엔트로피
손실(v4)   = Σ(토큰마다 교차 엔트로피 × 가중) ÷ Σ 가중        가중 = 칸 값 토큰 1 · 그 밖 0.1
```

기울기는 Qwen 을 **거꾸로 지나** 투영기에만 닿는다. Qwen 은 얼려 있어 지나가기만 한다.

⚠️ **왜 가중인가** — v2 의 캡션 손실은 **서식 글자까지 전부** 맞히는 손실이다. "다가오는 물체: … / 먹이 냄새: …" 의 틀 글자는 입력과 무관한 상수라 쉽게 맞히고,
정작 가려야 할 칸(왼쪽/오른쪽 · 개수)은 토큰 몇 개뿐이다 — 손실이 0.1 까지 내려가도 칸은 못 맞혔고, 섞은 배선의 손실이 오히려 낮았다(10장). 이것이 틀 손실로 설명된다(연구 노트 12 §4).

| v4 가중 규칙 | 내용 |
|---|---|
| 칸 값 구간 | 캡션은 `: 값 /`(`: ` 뒤부터 ` / ` 앞까지) · 행동 JSON 은 `:값`(`:` 뒤부터 `,` 나 `}` 앞까지) — `train_cli.value_spans` |
| 토큰에 옮기기 | 토크나이저의 글자 위치(`offset_mapping`)로 — 값 구간과 겹치는 토큰이 1, 아니면 `template_weight` · 끝 표시 `<|im_end|>` 도 0.1 |
| 왜 0 이 아니라 0.1 | 시스템 글에 캡션 서식이 없어 **서식을 배울 곳이 정답뿐**이다 — 0 으로 두면 서식을 못 배운다(I-7469 v1.5) |
| 시험 | 칸 구간이 맞는가 · 가중이 전부 같으면 균등 평균과 같은가 · 0 가중 토큰은 무시되는가(`tests/test_train_layerwise.py` · `test_stats.py`) |

## 4. 한 걸음 안에서 — 층별 역전파

### 4.1 왜 필요했나

처음엔 mlx 의 보통 방식(한 번에 미분)으로 돌렸다. 한 걸음 최대 메모리가 **토큰당 약 0.32 GB** 였다(226 토큰 → 102 GB · 191 토큰 → 90 GB).
Qwen3.8 의 선형 어텐션 층 48 개는 학습 모드에서 미분 가능한 경로를 타는데, 그 경로가 토큰마다 상태(층당 3 MB)를 남긴다.
mlx-lm 의 층별 재계산(`grad_checkpoint`)은 전체를 한 번에 평가하는 지연 평가에서는 듣지 않았다(켜도 꺼도 90~100 GB).

### 4.2 어떻게 하나 — `Trainer.grads`

```
1. 투영기로 입력 임베딩 x 를 만든다(여기서는 기울기를 끊는다)
2. 앞으로: Qwen 을 평가 모드(전용 커널 · 빠름)로 한 층씩 — 층마다 입력만 저장하고 즉시 평가
3. 머리: 마지막 은닉 → 정규화 → lm_head → 손실(v4: 가중), 마지막 은닉에 대한 기울기(cot)
4. 거꾸로: 학습 모드로 바꿔 마지막 층부터 한 층씩 vjp(저장한 입력으로) — 층마다 평가해 끊는다
5. 임베딩에 대한 기울기(cot)를 얻으면 ⟨투영기 임베딩, cot⟩ 의 기울기 = 투영기 기울기
```

한 번에 한 층 몫만 메모리에 든다. 결과는 한 번에 미분한 것과 **같다** — 작은 가짜 Qwen 으로 두 방식을 나란히 돌려 1e-6 안에서 확인했다(`tests/test_train_layerwise.py`).

### 4.3 걸음마다

`AdamW.update` → 평가 → **`mx.clear_cache()`**. 캐시 상한은 2 GB(`training_cache_limit_gb`).
캐시를 비우지 않았을 때는 걸음마다 쌓여 **13 시간 뒤 103 GB · 스왑 42 GB** 까지 갔다(2026-09-22).

| | 고치기 전 | 고친 뒤 |
|---|---|---|
| 걸음 사이 캐시 | 74.7 → 76.3 GB | **0.2 GB** |
| 한 걸음 최대 | 101.8 GB | **32 GB**(Qwen 29 GB 포함) |
| 걸음당 시간 | 92~314 s | 13~23 s(측정) · 실제 학습 5.6~7.6 s |

v4 는 입력 토큰이 줄어(자리 18 → 통과 채널 수) 걸음당 메모리가 이보다 작을 것으로 보지만 **`train-probe` 로 먼저 잰다.**

## 5. 메모리 가드 — 학습 전용 규칙

맥 한 대의 통합 메모리를 요구자 화면 · 에코마인드 라이브 · 다른 세션과 같이 쓴다. 정본은 `config/guard.yaml`.

| 때 | 조건 | 어기면 |
|---|---|---|
| 시작 전 | 시스템 메모리 여유 **≥ 80 %**(학습만의 예외 · 요구자 2026-09-22) · 잠금 `runs/.heavy.lock` 이 비어 있음 | 시작하지 않는다(끝 코드 2) |
| 도는 중(5 걸음마다) | 여유 **< 25 %** 또는 프로세스 전체 **> 50 GB** | 그때까지의 투영기를 `aborted-<단계>.safetensors` 로 저장하고 멈춘다(끝 코드 3) |
| 평가 · 성적표 | 평소 문턱 40 % + Qwen 28 GB | 시작하지 않는다 |

## 6. 명령

```bash
# 새 종류의 무거운 실행 전에는 먼저 짧게 잰다 (저장 없음 · 기록 runs/train-probe-*.jsonl)
uv run fly-connectome train-probe --steps 12                       # 기본 --brain real --dataset fly-loop-v2

# 한 뇌씩 — v4: 진짜 + 재배선 최소 3
uv run fly-connectome train --brain real                            # 기본 --dataset fly-loop-v2
uv run fly-connectome train --brain rewired-s0
uv run fly-connectome train --brain rewired-s1
uv run fly-connectome train --brain rewired-s2
# v1 자료 · v2 판을 다시 돌릴 때는 --dataset fly-loop-v1 --brain rewired (= s0)

# 캡션 단계 저장본에서 이어 행동 단계만
uv run fly-connectome train --brain real --resume-caption runs/projector-real-train-v1/stage1-caption.safetensors

# 전체 순서 스크립트 v4 — 압축 · 관문 → 학습 4 → 캡션 평가 8 → 성적표(씨앗 40 · 7 구성). 관문 통과 채널이 없으면 끝 코드 4 로 멈춘다
bin/run_full_v4.sh
bin/run_full_v4.sh --skip-train                       # 투영기가 이미 있을 때 — 압축 · 관문 → 평가 · 성적표만
# v2 순서(진짜 · 재배선 하나 · 성적표 5 구성)는 bin/run_full.sh 그대로
bin/run_full.sh --resume-real <진짜 배선 캡션 저장본>
```

`--brain` 은 `real` · `rewired`(= s0) · `rewired-s<K>`. `--dataset` 은 **묶음 이름**(`data/datasets/<이름>`)이다 — 묶음이 있으면 그 `train` · `eval` 나눔을 읽고, 없으면 예전처럼
`runs/dataset-<이름>` 조각(검증은 `--val`)을 읽는다. 어느 쪽을 읽었는지는 `meta.json` 의 `data` 에 남는다(묶음이면 `SHA256SUMS` 의 해시 · v4 는 압축기 폴더와 통과 채널까지).
`fly-loop-v1` 묶음과 `runs/` 조각은 특징 · 순서 · 정답이 **전부 같다**(2026-09-23 대조).

⚠️ **끝난 학습은 덮어쓰지 않는다** — 결과 폴더에 `final.safetensors` 가 있으면 `train` 이 시작하지 않는다(끝 코드 2).
같은 판으로 다시 돌리려면 폴더를 옮긴 뒤, 규칙을 바꿨으면 판을 올린다.

**이어 가기**의 세부: 저장본을 불러오고 → 캡션 단계가 썼을 난수만 소비해(순서를 건너뛰기) → 행동 단계의 예시 순서가 처음부터 돈 것과 **같게** 한다.
저장본의 sha256 을 `meta.json` 의 `caption_stage_from` 에 남긴다.

## 9. 확인 체크리스트

- [ ] 시작 전 `memory_pressure | tail -1` ≥ 80 % · `ollama ps` 로 다른 큰 모델이 없는지 · `runs/.heavy.lock` 이 비어 있는지
- [ ] v4: `compress fit` · `compress gate` 를 먼저 돌려 통과 채널이 있다(09장 4절)
- [ ] `train-probe` 기록이 있다(새 판 · 새 자료마다)
- [ ] `train.log` 의 `[mem]` 이 평탄(peak 약 32 GB 이하 · cache < 1 GB)
- [ ] 끝나면 `meta.json` 의 `qwen_fingerprint.unchanged: true`
- [ ] 학습 규칙을 바꿨으면 `TRAIN_RULE.version` 을 올렸다(결과 폴더 이름이 바뀐다)
