# 09. 평가와 대조군

> 2부 Qwen 연결 · 넷째 장. 코드: `src/moai_echomind_fly/loop/train_cli.py`(`eval-caption`) · `scorecard.py` · `linear_probe.py`.
> 증거: [W loop 3.3 ~ 3.5](../requirements/20260921-233859-3340_fly-connectome-closed-loop-loop_walkthrough.md).

## 1. 세 가지 잣대

손실이 내려갔다는 것만으로는 아무것도 말할 수 없다(08장 3절 — 틀 글자만 맞혀도 내려간다). 그래서 세 가지로 잰다.

| 잣대 | 묻는 것 | Qwen | 무게 |
|---|---|---|---|
| **캡션 평가** | Qwen 이 신호를 읽어 **상황을 말하나** | 씀 | 29 GB · 약 6 분 |
| **성적표** | 신호로 **몸을 잘 움직이나** · 다른 방식보다 나은가 | 씀 | 29 GB · 약 1.5 시간 |
| **선형 검사** | 신호 **자체에** 정보가 있나(Qwen · 투영기 없이) | 안 씀 | CPU 14 s |

그리고 모든 잣대에서 **진짜 배선을 섞은 배선과 나란히** 놓는다.

## 2. 캡션 평가 — `fly-connectome eval-caption`

```bash
uv run fly-connectome eval-caption --brain real    --checkpoint stage1-caption
uv run fly-connectome eval-caption --brain rewired --checkpoint final
```

1. 학습에 안 쓴 씨앗(`eval` 나눔 · 105 결정)마다 캡션을 **생성**시킨다(탐욕 · 최대 60 토큰).
2. 생성 글과 정답 글을 칸으로 쪼갠다(`caption_fields` · `_sub`).
3. 칸마다 정확도를 재고, **최빈값 기준선**(가장 흔한 답만 계속 말하면 몇 점인가)과 나란히 적는다.

| 칸 | 뜻 |
|---|---|
| `loom_present` | 다가오는 물체가 있나 |
| `loom_side` · `loom_distance` · `loom_motion` | 물체의 쪽 · 거리 · 움직임 |
| `odor_side` · `odor_level` | 냄새 쪽 · 세기 |
| `legs` | 다리 접촉 개수 |

결과는 `runs/projector-<뇌>-train-v2/eval-caption-<저장본>.json`(정확도 · 기준선 · 예시 8 개).

**읽는 법**: 기준선보다 확실히 높아야 "읽었다". 그리고 **진짜 배선이 섞은 배선보다 높아야** "초파리 배선 덕에 읽었다".

## 3. 성적표 — `fly-connectome scorecard`

```bash
uv run fly-connectome scorecard --seeds 2000-2009
```

같은 씨앗 10 개(학습 · 평가 자료에 없는 것)를 다섯 방식으로 돌린다.

| 구성 | 앞(인코더) | 뒤 | 가르는 것 |
|---|---|---|---|
| **vector**(본 설계) | 진짜 배선 → 채널 벡터 → 투영기(학습) | Qwen | — |
| text | 진짜 배선 → 글 요약(채널마다 발화율 상위 단위) | Qwen(학습 없음) | 벡터가 글보다 나은가 |
| no_circuit | 세계의 원시 숫자(물체 방위 · 크기 · 냄새 농도 · 다리 힘) | Qwen(학습 없음) | 초파리 뇌를 거치는 것이 도움이 되나 |
| **rewired**(대조군) | 섞은 배선 → 채널 벡터 → 투영기(**똑같이 학습**) | Qwen | **초파리 배선 덕인가** |
| no_llm | 진짜 배선 → 하강 뉴런 그대로(명령 없음) | 없음 | Qwen 이 더한 것이 있나 |

| 지표 | 뜻 |
|---|---|
| `reach_rate` | 먹이 도착률(**주 지표**) |
| `final_food_mm_mean` | 끝났을 때 먹이까지 평균 거리 |
| `avoid_rate` | 다가오는 물체를 안 부딪힌 비율 |
| `schema_violations` | 행동 JSON 형식 위반(위반이면 직전 행동 유지) |

### 문구 규칙 — 코드가 정한다 (R 2.0-6)

```python
beats = vector.reach_rate > rewired.reach_rate  or  vector.avoid_rate > rewired.avoid_rate
wording = "초파리 배선 벡터가 섞은 배선보다 나았다" if beats \
     else "섞은 배선 대조를 이기지 못했다 — '초파리 뇌'라는 말을 쓰지 않는다"
```

`scorecard.json` 에 `vector_beats_rewired` 와 `wording` 이 그대로 남는다. 보고서는 이 문구를 따른다 — 사람이 고쳐 쓰지 않는다.

⚠️ 정직 목록: no_circuit 에는 영상 이미지를 주지 않는다(mlx-lm 은 Qwen 의 글 부분만 올린다) · 걷기 리듬은 FlyGym 제어기가 만든다.

## 4. 선형 검사 — `fly-connectome linear-probe`

캡션 평가가 찍기 수준일 때 **어디가 막혔는지** 가르는 도구다.

```bash
uv run fly-connectome linear-probe --dataset fly-loop-v1     # CPU · 약 14 s · runs/linear-probe-*.json
```

| 방법 | 내용 |
|---|---|
| 분류기 | 선형(능선 회귀 · 이중 형태 — 차원 3.2만 > 표본 581 이라 581 × 581 행렬만 푼다) |
| 전처리 | 학습 자료 평균으로 중심화(안 하면 크게 떨어진다 · 실측) |
| 규제 세기 | 학습 자료 안에서 5 겹 교차검증으로 {0.01 … 10⁴} 중 고름 |
| 정확도 | 학습에 안 쓴 `eval` 나눔에서 |

| 결과 | 뜻 |
|---|---|
| 찍기보다 높다 | 신호에 정보가 있다 → **투영기 · 학습(전달)** 이 Qwen 에 못 넘긴 것 |
| 찍기와 같다 | 신호(또는 특징 만드는 법)에 정보가 없다 → **앞쪽(1부)** 을 고쳐야 한다 |

지금 명령은 **9 채널 전부를 한꺼번에** 넣어 재고, 그 결과만 파일(`runs/linear-probe-20260923-031800.json`)에 남긴다.
**칸에 맞는 채널만** 넣은 결과(시각 → 물체 · 몸 → 다리 등 · 10장의 핵심 근거)는 같은 함수(`probe_field`)로 채널을 골라 잰 값인데,
⚠️ **실행 기록 파일이 없고 W loop 3.5 에만 적혀 있다.** 다시 재려면 채널을 고르는 옵션을 명령에 더해 기록을 남기는 것이 먼저다(10장 할 일).

## 5. 판정 순서

```
선형 검사가 찍기 수준?  ── 예 ──► 1부(신호 · 채널 · 인코더)를 고친다
        │ 아니오
        ▼
캡션 평가가 찍기 수준?  ── 예 ──► 2부 전달(투영기 크기 · 입력 차원 · 손실 · 자료 양)을 고친다   ◄── 지금 여기
        │ 아니오
        ▼
성적표에서 vector > rewired?  ── 아니오 ──► 문구 규칙 발동 · 원인을 가른다
        │ 예
        ▼
"초파리 배선 벡터가 섞은 배선보다 나았다" — 보고 가능
```
