07. 투영기와 Qwen 잇기

2부 Qwen 연결 · 둘째 장. 코드: src/moai_echomind_fly/loop/{qwen,fly_prompt,projector,compress}.py · 설정 config/llm.yaml · config/compress.yaml. 배경: 연구 노트 11 §2 · §3 · 12 §2 ~ §4.

▶ 투영기 판 — train-v2(v1 자료 결과 · 2층 MLP 3,187만) · train-v4(압축 벡터 → 선형 · 133만 · 진짜 배선만 끝냄 · 뇌 사이 비교는 하지 않는다) · train-v5(2026-09-24 · v4 + 크기를 맞춘 압축 compress-v3) · train-v6(v5 규칙 · 자료 fly-loop-v4 · 입력 시각 · smell_ln · 공간 · 매개변수 91.6 만 — 1판 정본 · 1판 정리) · train-v7(v6 + 캡션 되새김 0.5 · 지금 코드의 규칙 판 · 성적표 p 0.056 못 넘음). 이 장은 v2 와 v4~v7 을 나란히 적는다(v4~v7 은 투영기 모양이 같고 입력 크기 · 자료 · 되새김만 다르다).

1. 구도 — 이미지 자리에 초파리 신호

Qwen3.8 은 원래 이미지를 읽을 수 있다: 이미지 → 비전 인코더 → 합치개 → <|vision_pad|> 자리 → 언어 모델. 우리는 비전 인코더와 합치개를 아예 올리지 않고, 같은 자리에 초파리 신호 → 투영기 를 넣는다.

이미지 읽는 LLM(LLaVA 식) 이 프로젝트
앞(인코더 · 얼림) 비전 인코더 초파리 뇌(1부)
가운데(학습) 투영기 투영기(+ v4: 그 앞의 압축기 — 학습이 아니라 맞춤)
뒤(생성기 · 얼림) 언어 모델 Qwen3.8-27B

2. Qwen 을 직접 올린다 — loop/qwen.py

항목 내용
가중치 ~/.omlx/models/orcarouter/Qwen3.8-27B-Uncensored-MLX-8bit(요구자 선택 · 공식판이 아닌 파생판)
방법 서버(oMLX · Ollama)를 띄우지 않고 우리 프로세스가 mlx-lm 공개 API 로 직접 읽는다(load · generate_step(input_embeddings=))
비용 8.1 s · 28.6 GB · 해독 약 10 tok/s · 입력 읽기 약 400 tok/s
모양 은닉 5,120 차원 · 층 64 개(그중 선형 어텐션 GatedDeltaNet 48 개)
얼림 올리자마자 model.freeze() — 학습 대상이 아니다
생각 모드 끔(enable_thinking: false) · 복호는 탐욕(온도 0) — 같은 입력이면 같은 출력
학습 때 역전파 층마다(기본) 또는 층 k 개씩 묶어(backprop_chunk · 2026-10-01 · 기울기 같음 시험 · 효과는 train-probe --chunk 로 잴 예정) — 08장 4.2

끼워 넣기가 되는지 먼저 확인했다: 글 토큰 대신 그 토큰의 임베딩을 넣으면 로짓이 정확히 같다(차이 0.0). 그러니 임베딩 자리에 다른 벡터를 넣을 수 있다.

3. 입력 모양 — 글 사이에 신호 자리 — loop/fly_prompt.py

채팅 틀에 글과 채널 태그 + 자리 표시 토큰을 섞는다. 자리 표시는 Qwen 이 원래 이미지 임베딩을 끼우는 <|vision_pad|>(토큰 248055)다.

[system] 너는 초파리의 뇌다. 아래 <채널> 사이에는 초파리 회로가 지난 300ms 동안 낸 신경 신호가 들어 있다.
         지금 무엇이 느껴지는지 정해진 서식으로 한 줄로 답한다.            ← 캡션용
[user]   지금 무엇이 느껴지나?
         <vision>▢▢</vision> <touch>▢▢</touch> <hearing>▢▢</hearing> <smell>▢▢</smell> <taste>▢▢</taste>
         <courtship>▢▢</courtship> <value>▢▢</value> <body>▢▢</body> <motor>▢▢</motor>
[assistant] (여기부터 생성)

▢ 가 <|vision_pad|> 하나. 행동용은 시스템 글이 목표와 JSON 형식을 알려 주고 질문이 "지금 어떻게 움직일까?"다.

판 자리 표시 어느 채널
train-v2 채널마다 k = 2 개 · 모두 18 개 9 채널 전부
train-v4 채널마다 1 개 · 모두 = 관문 통과 채널 수 압축 관문(09장 4절)을 통과한 채널만 <채널>▢</채널>
입력(v2 기준) 길이 첫 자리 표시 위치 정답 길이
캡션 154 토큰 68 번째 약 38 토큰
행동 198 토큰 112 번째 약 28 토큰

QwenLM.splice 가 자리 표시를 투영기 출력으로 순서대로 바꾼 임베딩을 만든다. 나머지 토큰은 Qwen 의 원래 임베딩 그대로다 — "일반 텍스트도 들어가고 초파리 신호도 들어가는" 모양(요구자).

4. 투영기 — loop/projector.py

채널마다 따로인 작은 신경망이다. 출력 토큰은 RMS 를 Qwen 토큰 임베딩의 평균 RMS(0.01517 · 토큰 1000~2999 에서 잰다)에 맞춘다 — 소프트 토큰이 글 토큰과 같은 크기로 들어가게.

4.1 train-v2 — v1 자료 결과(옛 판)

채널 벡터 (d 차원) ──► Linear(d → 256) ──► GELU ──► Linear(256 → 2 × 5,120) ──► 토큰 2 개 [2, 5,120]
9 채널을 순서대로 이어 붙여 [18, 5,120]
부분 계산 매개변수
첫 층(입력 → 256) 31,950 × 256 + 9 × 256 8,181,504
둘째 층(256 → 10,240) × 9 채널 9 × (256 × 10,240 + 10,240) 23,685,120
합계 31,866,624 (Qwen 27B 의 약 0.1 %)

⚠️ 표본은 581 개다. 매개변수가 표본의 5 만 배를 넘는다 — 10장에서 이것이 막힌 곳으로 드러났다(3.2만 차원을 통째로 넣으면 선형 검사에서도 차이가 사라진다).

4.2 train-v4 · train-v5 — 압축 벡터 → 선형 토큰 하나

채널 벡터 (d 차원) ──► [압축기 PCA · k 64 · (v3) ÷ 채널 평균 크기 · 맞춤(기울기 없음)] ──► Linear(64 → 5,120) ──► 토큰 1 개
관문을 통과한 채널만 · 순서대로 이어 붙여 [통과 채널 수, 5,120]
설정(TRAIN_RULE v4) 값 뜻
input compress · v4 = compress-v2(모든 뇌 · 채널 64 고정) · v5 = compress-v3(+ 채널마다 평균 크기 1 · 4.3) 입력은 09장 4절 의 압축기 출력(runs/compress-<자료>-<판>/<뇌>.npz)
kind linear 선형 하나 — 인코더 표현이 좋으면 선형 사상으로도 된다(LiMBeR · 연구 노트 12 [4])
k 1 채널당 소프트 토큰 수
width 0 가운데 층 없음
크기 계산
채널 하나 k_in × 5,120 + 5,120 — compress-v2 · v3 는 k_in 64 라 332,800
자료 v2 관문 통과 채널 4(시각 · 촉각 · 미각 · 몸) 1,331,200(약 133 만 · train-v2 의 1/24)

압축기는 뇌마다(진짜 · 재배선 각각) 학습 나눔으로만 맞추고, 재배선에도 같은 규칙으로 따로 맞춘다 — 대조군 절차를 같게. 관문을 통과한 채널이 하나도 없으면 v4 학습을 하지 않는다(F-004 규칙 · GuardRefused).

4.3 입력 크기를 맞추는 까닭 — compress-v3 (2026-09-24 · 결과 뒤 고침)

v4 를 돌려 보니 재배선 뇌가 진짜 배선보다 먼저 배웠다 — 캡션 450 걸음 손실이 진짜 3.42 · 재배선 s0 2.12. 원인은 신호의 내용이 아니라 입력의 크기였다. compress-v2 는 방향(PCA 축)만 맞추고 크기는 그대로 두어, 같은 64 차원이라도 뇌 · 채널마다 벡터 크기가 달랐다.

채널(64 차원 벡터의 평균 크기 · 자료 v2 학습 나눔) 진짜 배선 재배선 s0 · s1 · s2
시각 0.90 1.77 · 1.80 · 2.07
몸 8.31(첫 축 하나가 5.0) 1.60 · 1.70 · 2.13
촉각 0.17 0.03 ~ 0.08
미각 0.07 0.01 ~ 0.06

투영기는 선형 + 편향이다. 처음에는 편향(입력과 무관한 상수 토큰)으로 손실을 줄이다가, 입력 쪽 가중치가 자라면서 신호를 쓰기 시작한다. 입력이 클수록 같은 학습률에서 그 전환이 빠르다 — 그래서 시각 입력이 두 배인 재배선이 먼저 배웠다. 촉각 · 미각은 크기가 너무 작아 모든 뇌에서 사실상 상수 토큰이었다. 이것은 "진짜 배선이 더 나은가"와 무관한 차이라, 절차가 같다는 대조군 원칙이 깨진다(요구자 결정 A · 2026-09-24 10:4x — v4 를 멈추고 다시).

compress-v3 규칙(config/compress.yaml): 압축 뒤 채널마다 학습 나눔의 평균 L2 크기로 나눠 모든 뇌 · 채널의 평균 크기를 1 로 맞춘다(unit_scale · 크기 0 채널은 scale_floor 1e-6 으로 나눔).

선택 까닭
채널 전체를 한 수로 나눈다(축마다 나누지 않는다) 축마다 백색화하면 분산이 0 에 가까운 꼬리 축(미각 64 번째 축 표준편차 0.000)이 잡음으로 부푼다 — 축 사이 비율(PCA 스펙트럼)은 그대로 둔다
크기는 학습 나눔으로만 잰다 평가 자료를 보지 않는다(압축기와 같은 원칙)
뇌마다 따로 잰다 재배선도 같은 규칙으로 — 모든 뇌가 같은 크기로 들어간다

압축 방향은 v2 와 같고 scale 하나만 더 저장한다. 관문 판정도 v3 특징으로 다시 했다(릿지는 크기에 민감) — 통과 채널은 시각 · 촉각 · 미각 · 몸(칸 7)으로 v2 와 같고, 적용 뒤 모든 뇌 · 채널의 평균 크기가 1.000 이었다(runs/compress-fly-loop-v2-compress-v3/). 학습 규칙 train-v5 는 v4 에서 압축 판만 v3 로 바꾼 것이다(08장 2절).

5. Qwen 이 정말 안 바뀌었나 — 가중치 지문

파인튜닝이 아니라는 것을 말이 아니라 기록으로 남긴다. 학습 시작 전과 끝난 뒤 Qwen 전체 가중치의 지문을 찍는다(train_cli.qwen_fingerprint): 매개변수 이름 순으로 각 텐서의 합 · 절댓값 합을 SHA-256 에 넣는다.

학습 전 뒤 같음
진짜 배선 train-v2 a4cfcb8d… a4cfcb8d… ✅
섞은 배선 train-v2 a4cfcb8d… a4cfcb8d… ✅

결과는 투영기 meta.json 의 qwen_fingerprint.unchanged 에 남는다. 가중치 폴더는 받은 그대로라 oMLX · Ollama 에서 쓰던 모델에도 영향이 없다. v4 학습에서도 같은 지문을 찍는다.

6. 학습 전에 신호를 넣으면

투영기가 무작위 상태일 때 캡션을 시키면 "어둠 속에서 희미한 진동과 함께, 아무것도 없는 공허함 속에…" 같은 말을 지어낸다. Qwen 은 초파리 뉴런 발화를 본 적이 없으니 당연하다 — 다리를 가르쳐야 한다(08장).

7. 확인 체크리스트

  • [ ] config/llm.yaml 의 weights 경로가 있다 · 올리기 전 메모리 여유(40 % + 28 GB)
  • [ ] 자리 표시 수 = 채널 수 × k(v2: 18 · v4: 통과 채널 수 × 1) — 다르면 splice 가 오류를 낸다
  • [ ] v5: runs/compress-<자료>-compress-v3/gate.json 의 passed_channels 가 비어 있지 않다(자료 v2: 시각 · 촉각 · 미각 · 몸)
  • [ ] v5: 압축기 meta.json 에 채널마다 scale 이 있고, 압축 뒤 평균 크기가 뇌 · 채널 모두 1 이다(4.3)
  • [ ] 학습 뒤 meta.json → qwen_fingerprint.unchanged: true
